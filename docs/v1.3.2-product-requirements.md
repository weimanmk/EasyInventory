# EasyInventory v1.3.2 产品需求文档（PRD）

文档状态：草案

目标版本：v1.3.2

创建日期：2026-06-11

适用仓库：`C:/Users/ww/Desktop/work/EasyInventory`

参考输入：`docs/repository-problem-analysis.md`

## 1. 背景

EasyInventory v1.3.1 已具备商品、客户、供应商、入库、出库、欠款、利润、单据、导入、备份恢复和诊断等核心能力。本地质量门禁表现良好：TypeScript 类型检查、Rust 格式检查、clippy、Rust 单测、前端构建、核心流程脚本、浏览器 E2E 和健壮性脚本均可通过。

但作为面向真实经营数据的本地桌面软件，v1.3.1 仍存在三个高优先级可靠性问题：

1. 客户端日志默认记录命令参数，可能落入客户姓名、电话、地址、金额、文件路径等敏感信息。
2. 应用启用 SQLite WAL 模式，但备份逻辑直接复制主数据库文件，备份完整性不够可靠。
3. 运行时 SQLite 连接未统一设置 `busy_timeout`，并发写入时可能出现瞬时 `database is locked`。

v1.3.2 定位为“数据安全与可靠性补丁版本”，不引入大功能，优先把真实用户经营数据的安全边界补齐。

## 2. 产品目标

### 2.1 核心目标

- 降低日志和诊断材料泄露经营数据的风险。
- 保证自动备份、手动备份和恢复前快照在 WAL 模式下具备一致性。
- 提升本地 SQLite 并发写入韧性，减少锁冲突导致的失败。
- 保持 v1.3.1 用户升级路径简单，不要求手动迁移数据库。

### 2.2 成功指标

| 指标 | 目标 |
| --- | --- |
| 日志敏感字段泄露 | 常见敏感字段默认脱敏，不记录完整业务 payload |
| WAL 备份一致性 | 备份包含 checkpoint 后最新已提交数据 |
| 备份可用性 | 备份完成后可被打开并通过完整性检查 |
| 并发写入稳定性 | 使用运行时连接的并发测试不出现瞬时锁失败 |
| 发布质量 | `npm run check`、`npm run package:smoke`、`npm run release:manifest` 通过 |

## 3. 非目标

v1.3.2 不处理以下事项：

- 不做多人协作、云同步、权限角色和多门店能力。
- 不重构整个前端 API 类型系统。
- 不大规模拆分 `SettingsPage.tsx`、`reports.rs`、`generalization.rs`。
- 不引入新的数据库迁移框架，除非修复必须。
- 不改变现有业务流程、价格规则、库存计价和报表口径。
- 不引入登录、账号体系或联网服务。

## 4. 用户与场景

### 4.1 目标用户

- 小型商贸、批发、配送、门店经营者。
- 使用本地 SQLite 数据库保存商品、客户、订单、欠款和利润数据的单机用户。
- 需要把日志、截图或诊断包发给开发者排查问题的用户。
- 维护 EasyInventory 开源项目的开发者。

### 4.2 关键使用场景

1. 用户保存客户、商品、订单失败后导出日志给开发者排查，日志不应直接暴露完整客户资料。
2. 用户每天首次启动应用触发自动备份，备份应包含最近一次已提交订单。
3. 用户在快速出库后立即手动备份，备份文件恢复后应能看到该订单和库存变动。
4. 用户连续执行入库、出库、打印、备份等操作，应用应尽量等待短暂数据库写锁，而不是立即失败。
5. 用户恢复备份前，系统自动创建恢复前快照，快照也应是一致的数据库文件。

## 5. 需求范围

v1.3.2 包含以下四个需求域：

| 需求域 | 优先级 | 说明 |
| --- | --- | --- |
| 日志与诊断脱敏 | P0 | 默认不记录完整业务参数，敏感字段统一脱敏 |
| SQLite 一致性备份 | P0 | 修复 WAL 模式下直接复制主库文件的风险 |
| 数据库锁等待策略 | P0 | 运行时连接统一设置 `busy_timeout` |
| 发布与验证补强 | P1 | 补充测试、发布说明和安全边界文档 |

## 6. 功能需求

### FR-1 日志默认摘要化

描述：

前端调用 Tauri command 时，日志只记录必要排障信息，不默认记录完整请求参数。

要求：

- 命令开始日志记录：命令名、调用时间或调用阶段。
- 命令成功日志记录：命令名、耗时、结果摘要。
- 命令失败日志记录：命令名、耗时、错误码、错误消息摘要。
- 默认不记录完整 `args`。
- 对确实需要排障的 details，必须先经过脱敏函数。

验收标准：

- 新建客户、供应商、商户资料、订单后，日志中不能出现完整电话、完整地址和完整客户姓名 payload。
- `write_client_log` 仍能记录命令名和错误摘要，便于定位失败点。
- 已有日志写入测试继续通过，并新增脱敏测试。

### FR-2 统一敏感字段脱敏规则

描述：

新增统一脱敏能力，覆盖前端日志 details、后端日志消息和诊断导出中的敏感文本。

建议脱敏规则：

| 字段类型 | 示例字段 | 规则 |
| --- | --- | --- |
| 电话 | `phone`、`merchantPhone`、`contactPhone` | 保留前 3 位和后 2 位，中间替换为 `***` |
| 地址 | `address`、`customerAddress`、`merchantAddress` | 保留前 4 个字符，其余替换为 `***` |
| 客户/供应商名称 | `customerName`、`supplierName` | 保留首尾字符，中间替换为 `*`；短文本直接替换为 `***` |
| 文件路径 | `filePath`、`databasePath`、`backupPath` | 只保留文件名或末级目录 |
| 订单明细 | `items`、`lines`、`details` | 只记录条数和字段名，不记录完整内容 |

验收标准：

- 脱敏函数有单元测试。
- 循环引用、Error 对象、数组和普通对象都能安全处理。
- 脱敏失败时不影响主业务流程。

### FR-3 诊断导出增加隐私边界

描述：

诊断包、数据自检导出和日志目录打开等操作应明确提示用户注意隐私，并尽量输出脱敏后的诊断信息。

要求：

- 诊断导出前展示隐私提示。
- 诊断包中的日志默认使用脱敏内容。
- 数据库路径、备份路径、导出路径只显示必要定位信息。
- README 或 Release Notes 中补充“反馈问题前请脱敏”的说明。

验收标准：

- 用户从设置页导出诊断包前能看到隐私提示。
- 导出的诊断内容不包含完整手机号、完整地址和完整数据库路径。

### FR-4 使用 SQLite 一致性备份机制

描述：

替换直接复制主数据库文件的备份方式，确保 WAL 模式下备份文件包含最新已提交数据。

要求：

- 手动备份、自动备份、恢复前快照都使用一致性备份路径。
- 优先使用 SQLite backup API。
- 如保留文件复制方案，必须在复制前执行 checkpoint，并确认无活跃写事务。
- 备份完成后执行基础可用性校验。

验收标准：

- 在 WAL 模式下写入一笔订单或设置项后立即备份，恢复备份可读到该数据。
- 备份文件可被 SQLite 打开，并通过基础完整性检查。
- 自动备份和手动备份行为一致。
- 备份失败时返回清晰错误，不写入成功备份记录。

### FR-5 恢复流程保留恢复前一致性快照

描述：

恢复备份前，系统应先为当前数据库创建一致性快照，避免用户误恢复后无法回退。

要求：

- 恢复前快照不能直接复制可能未 checkpoint 的主库文件。
- 快照创建失败时中止恢复。
- 恢复完成后清理旧 sidecar 文件，避免 WAL 状态污染。
- 恢复结果明确展示恢复来源和恢复前快照路径。

验收标准：

- 模拟恢复失败时，原数据库不被替换。
- 恢复前快照可独立打开。
- 现有 `restore_database_file_creates_snapshot_and_replaces_database` 测试继续通过，并补充 WAL 场景测试。

### FR-6 运行时连接统一设置 `busy_timeout`

描述：

所有通过 `AppState::connection()` 创建的 SQLite 连接都应具备一致的锁等待策略。

要求：

- 在 `AppState::connection()` 中设置 `busy_timeout`。
- 建议默认等待时间为 10 秒。
- 测试连接与生产连接尽量复用相同配置路径。
- 不改变事务边界和现有业务语义。

验收标准：

- 使用 `AppState::connection()` 的并发入库、出库或收款测试通过。
- 并发写入遇到短暂锁竞争时不会立即失败。
- 锁等待超时后返回可读错误。

### FR-7 增加可靠性回归测试

描述：

为 v1.3.2 的三项核心修复增加自动化测试。

最低测试范围：

- 日志脱敏测试。
- WAL 模式下备份一致性测试。
- 恢复前一致性快照测试。
- 运行时连接 `busy_timeout` 配置测试。
- 使用运行时连接的并发写入测试。

验收标准：

- `npm run typecheck` 通过。
- `npm run format:rust` 通过。
- `npm run lint:rust` 通过。
- `npm run test:rust` 通过。
- `npm run e2e:flows` 通过。
- `npm run e2e:browser` 通过。
- `npm run audit:robustness` 通过。

### FR-8 发布材料更新

描述：

v1.3.2 发布材料应明确这是可靠性与数据安全补丁版本。

要求：

- 更新版本号：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。
- 更新 README 当前版本和下载说明。
- Release Notes 说明日志脱敏、备份一致性、数据库锁等待三项修复。
- 新增或更新安全反馈说明，建议文件为 `SECURITY.md`。
- 发布前运行 `npm run release:verify`。

验收标准：

- 版本号一致为 `1.3.2`。
- Release Checklist 可用于 v1.3.2 发布。
- 生成的 release manifest 包含安装包和便携 EXE 的 SHA256。

## 7. 非功能需求

### 7.1 兼容性

- 必须兼容 v1.3.1 现有数据库。
- 不要求用户手动导出/导入数据。
- 不改变应用数据目录结构。
- 不影响现有备份列表读取。

### 7.2 安全性

- 不上传任何数据到云端。
- 不新增联网依赖。
- 默认日志和诊断信息不得包含完整敏感业务数据。
- 备份和恢复错误不得泄露过多本机路径。

### 7.3 性能

- 日志脱敏不能显著影响普通命令调用。
- 备份耗时可随数据库大小增长，但必须有明确失败反馈。
- `busy_timeout` 只在锁竞争时等待，不影响无竞争场景。

### 7.4 可维护性

- 修复保持小步、局部。
- 不引入复杂抽象。
- 备份、日志、连接配置分别保持单一职责。
- 新增测试应覆盖真实风险，而不是只检查源码字符串。

## 8. 用户体验要求

### 8.1 备份成功反馈

备份成功后继续展示备份路径，但路径可按“文件名 + 所在目录入口”展示，避免在日志中记录完整路径。

### 8.2 诊断导出提示

诊断导出前建议提示：

```text
诊断包可能包含运行日志和本机路径信息。导出前系统会尽量脱敏，但提交给他人前仍建议检查内容，避免包含客户、电话、地址、真实订单或库存金额。
```

### 8.3 锁等待失败提示

如果数据库锁等待超时，建议提示：

```text
当前数据库正被其他操作占用，请稍后重试。若频繁出现，请先完成正在进行的备份、导入或批量操作。
```

## 9. 数据与迁移

v1.3.2 原则上不新增业务表，不改变订单、库存、客户和报表口径。

若实现一致性备份需要新增备份校验字段，可优先复用 `backup_logs.message`，避免新增 schema。若必须新增字段，应通过兼容迁移补齐，并增加旧库升级测试。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 脱敏过度导致排障信息不足 | 开发者定位问题变慢 | 保留命令名、错误码、耗时、结果摘要 |
| 脱敏遗漏字段 | 仍可能泄露隐私 | 建立字段规则和回归测试 |
| SQLite backup API 接入复杂 | 备份修复延期 | 先封装单一 `create_consistent_backup` 函数 |
| 备份期间写入冲突 | 用户操作失败或备份失败 | 统一锁等待，备份失败不写成功记录 |
| 版本号多处不一致 | 发布混乱 | 发布前增加版本一致性检查 |

## 11. 验收清单

发布 v1.3.2 前必须满足：

- [ ] 日志默认不记录完整业务 payload。
- [ ] 客户、供应商、商户、订单相关敏感字段已脱敏。
- [ ] WAL 模式下写入后立即备份可恢复最新数据。
- [ ] 恢复前快照为一致性数据库文件。
- [ ] `AppState::connection()` 统一设置 `busy_timeout`。
- [ ] 新增可靠性回归测试。
- [ ] `npm run check` 通过。
- [ ] `npm run release:verify` 通过。
- [ ] README、Release Notes、Release Checklist 已更新到 v1.3.2。
- [ ] 发布包 SHA256 已生成并记录。

## 12. 暂缓事项

以下事项进入 v1.3.3 或后续版本评估：

- 数据库迁移版本化机制。
- 前端 typed command map。
- `SettingsPage.tsx` workflow 拆分。
- `reports.rs`、`generalization.rs` 大文件拆分。
- 真实 Tauri IPC + SQLite 桌面端冒烟测试。
- Bundle size 预算和分析工具。
- `CHANGELOG.md`、`SUPPORT.md`、更完整的开源治理文档。

## 13. 版本定位总结

v1.3.2 是补丁版本，不追求新增显眼功能。它的价值在于让用户更放心地把 EasyInventory 用在真实经营数据上：日志更克制、备份更可信、数据库写入更稳。实现上应坚持小范围修复和强回归验证，避免把后续架构优化提前并入本版本。
